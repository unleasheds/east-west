# EastWest Halal Travel — Full-Stack App

Airbnb-style rebranded travel platform for halal-friendly holidays.

## Stack

| Layer    | Tech                                   |
|----------|----------------------------------------|
| Frontend | React 18 · Vite · Tailwind CSS · Zustand · React Router |
| Backend  | NestJS · TypeORM · PostgreSQL          |
| Comms    | WhatsApp deep-link integration         |

## Design

Airbnb-inspired UI with EastWest brand colours:
- **Coral** `#E07B54` — primary CTA
- **Halal green** `#22C55E` — trust badges
- **Sand** `#F7F5F2` — page background
- **Inter** — typography

## Project structure

```
east-west/
├── client/   # React + Vite + Tailwind
└── server/   # NestJS + TypeORM + PostgreSQL
```

## Quick start

### 1. Database
```bash
# create a local PostgreSQL database
createdb eastwest_db
```

### 2. Server
```bash
cd server
cp .env.example .env    # fill in DB credentials
npm install
npm run start:dev       # runs on :3001
```

### 3. Client
```bash
cd client
npm install
npm run dev             # runs on :5173
```

## SEO

The app is a client-rendered SPA, so the production client is served by
`client/server.mjs` — a zero-dependency Node server that rewrites each
response's `<head>` for the URL being requested. Search engines execute
JavaScript, but social and AI crawlers (WhatsApp, Facebook, Slack, LinkedIn, X)
do not; without server-side head injection every share preview would fall back
to the same generic shell.

**One source of truth.** All titles, descriptions, canonicals, hreflang
alternates, Open Graph/Twitter tags and JSON-LD are generated by
`client/shared/seo.js`. Both the edge server and the React `<Seo>` component
(`src/components/seo/Seo.tsx`) call the same `renderHeadTags()`, so what a
crawler sees on first load matches what the SPA maintains during navigation.
**Edit metadata there, not in `index.html`** — that file only carries the
`<!--seo:head-->` and `<!--seo:body-->` injection markers.

What is implemented:

- Per-URL title, description, canonical, Open Graph and Twitter cards
- `hreflang` for `en` / `ms` / `ar` via `?lang=`, plus `x-default`
- JSON-LD: TravelAgency, WebSite + SearchAction, Product + Offer +
  AggregateRating (emitted only when real reviews exist), BreadcrumbList,
  FAQPage, ContactPage with both office addresses
- Dynamic sitemaps generated from live package data, with `lastmod` and image
  entries; republished at the site root by the edge server
- Real `404` status codes for unknown routes and dead package slugs, and `503`
  (not `404`) when the API is unreachable, so an outage cannot deindex packages
- `noindex` on account and admin routes; `www` → apex and trailing-slash 301s
- `<noscript>` package content for crawlers that do not render JavaScript

### Environment

| Variable | Where | Purpose |
|----------|-------|---------|
| `API_URL` | client | API origin the edge server fetches package data from |
| `PUBLIC_SITE_URL` | server | Canonical origin used in sitemaps (default: production) |
| `SEO_ALLOW_INDEXING` | server | Set to `false` on staging to serve a blanket `Disallow: /` |
| `CANONICAL_REDIRECT` | client | Set to `false` to disable the apex-domain redirect |

### Verifying locally

```bash
cd client
npm run build && node server.mjs        # serves on :8080
curl -s localhost:8080/ | grep '<title>'
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/package/does-not-exist   # 404
```

### After deploying

1. Submit `https://eastwesthalaltravel.com/sitemap.xml` in Google Search Console.
2. Re-scrape a package URL with the Facebook Sharing Debugger and X Card
   Validator to refresh any cached previews.
3. Check Product and FAQ markup in the Rich Results Test.
